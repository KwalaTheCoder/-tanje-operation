تاریخ: ۱۳ نوامبر ۲۰۲۶ — Asia/Tehran

## نتیجه و وضعیت پذیرش

نسخه اصلاح‌شده در شاخه `demo/owner-presentation-polish` آماده بررسی کد است. ۱۳ گروه آزمون منطق/DOM-stub پاس شده‌اند. **تأیید نهایی برای جلسه مالک هنوز صادر نمی‌شود**؛ بررسی بصری و اجرای مرورگری نسخه اصلاح‌شده روی موبایل/دسکتاپ و تصاویر «بعد» در این محیط مسدود بوده است. آزمون منطقی جای آزمون مرورگر را نمی‌گیرد. PR باید Draft بماند تا این گیت بسته و مالک انتشار را تأیید کند.

1. هویت جنگلی/کاغذی/برنجی، فونت فارسی، RTL، ۸ بخش اصلی و نام شعب حفظ شدند؛ CSS تکمیلی با اندازه‌های سازگار و کاهش تزئینات اضافه شد.
2. داشبورد: ارزش موجودی پایان بازه، خرید دریافتی، فروش، بهای مرجع مواد فروش، دورریز، زیرآستانه، درخواست باز و شمارش مغایر؛ تعریف هر KPI کنار آن است.
3. فیلتر شروع/پایان بازه و شعبه به محاسبات واقعی متصل است. موجودی as-of پایان بازه است؛ گردش‌ها در بازه‌اند. جدول مقایسه همه شعب صریحاً از فیلتر شعبه مستقل نام‌گذاری شده است.
4. داده اولیه تازه از یک seed تعیین‌پذیر و مشترک ساخته می‌شود؛ مقادیر تصادفی و KPI مستقل وجود ندارد. نرخ و پورشن نمونه و مراجع مرتبط مشخص‌اند.
5. فرم جدید درخواست خرید و گردش محلی پیش‌نویس→ارسال→بررسی→تأیید نمایشی→دریافت مرتبط؛ دریافت جزئی و جلوگیری از دریافت بیش از مانده نیز لحاظ شده است. این تأییدها کنترل دسترسی واقعی نیستند.
6. فروش و مصرف recipe snapshot، پخش مرکزی→شعبه و دورریز به موجودی متصل‌اند؛ گزارش‌ها از همان records و افتتاحیه محاسبه می‌شوند.
7. گزارش موجودی، خرید، مصرف، دورریز، کارکنان و مقایسه شعب در گزارش مدیر کنار هم آمده‌اند؛ خروجی CSV و چاپ موجود فعال‌اند.
8. حالت ارائه مستقل به عنوان بخش نهم، با سناریو، نقش‌های پیشنهادی، فعالیت محلی و نقشه راه اضافه شده است. پنج مرحله آینده دقیقاً طرح/کشف/طراحی/Backend+Database/تست‌وپایلوت است.
9. همه صفحات برچسب دائمی «نسخه نمایشی، داده نمونه و ثبت محلی؛ بدون Backend/حساب/RBAC» دارند. Audit امن ادعا نشده؛ فعالیت محلی صریحاً قابل تغییر در مرورگر معرفی شده است.
10. داده احتمالی کلید قبلی حذف، reset یا خودکار migrate نشده است. فضای ارائه کلید جدا دارد؛ خرابی JSON/ساختار باعث توقف ثبت و امکان خروجی اصل داده می‌شود.
11. واردکردن متن ردیف‌ها قبل از ثبت، پیش‌نمایش تعداد معتبر و تأیید ثبت نهایی دارد. همان قالب متنی پنج‌ستونی با `|` حفظ شده؛ **ورود فایل CSV/XLSX واقعی پیاده نشده** و دکمه جعلی برایش وجود ندارد.
12. submit دوباره فرم ذخیره‌شده مسدود؛ مراجع تکراری و موجودی ناکافی رد؛ دریافت/شمارش/دورریز و تأیید نمایشی نیازمند تأیید کاربرند.
13. شمارش‌های جدید expected ثابت دارند؛ شمارش جدید، سابقه قبلی را با supersededBy نگه می‌دارد. هیچ تعدیل موجودی یا بدهی کارکنان خودکار ساخته نمی‌شود.

### دلایل مشخص محدودیت مرورگر

- `sites-preview start/status`: preview relay unavailable: No such file or directory.
- Playwright نصب‌شده بود؛ Chromium bundled وجود نداشت. Chromium سیستم هنگام launch با `socket() failed: Operation not permitted` متوقف شد. هیچ دانلود مرورگر، تغییر شبکه یا دورزدن sandbox انجام نشد.
- URL محلی file:// در مرورگر ابری طبق سیاست پروتکل ممنوع بود؛ این مسیر ادامه یا دور زده نشد.
- نسخه live با HTTPS در مرورگر ابری قابل بررسی بود و باگ اصلی در آن بازتولید شد، اما تغییرات branch منتشر نشده‌اند؛ این مشاهده اثبات تست نسخه اصلاح‌شده نیست.
- تصویر قبل در گفتگو از مرورگر نمایش داده شد؛ فایل مرورگر در runtime جداست و به checkout دسترس‌پذیر نبود. بنابراین هیچ مسیر تصویر ساختگی یا تصویر «بعد» جعلی داخل PR اضافه نشده است. تصاویر قبل/بعد و تست موبایل/دسکتاپ **تحویل ناقص باقی مانده‌اند**.

`tests/demo-browser.cjs` برای اجرای واقعی روی ایستگاه دارای Playwright و Chromium آماده است؛ هنوز پاس‌شده ادعا نمی‌شود. پس از اجرای موفق، تصاویر dashboard/presentation/mobile را در docs/screenshots ذخیره می‌کند. نسخه مبنا برای تصویر قبل باید جداگانه با همان viewport و تاریخ اجرا شود.

## محدودیت‌های باقی‌مانده محصول

LocalStorage فقط همین مرورگر است؛ عملیات چندکاربره، مجوز، تأیید مستقل واقعی، تراکنش سروری، ledger غیرقابل تغییر، WAC تولیدی، lot/FEFO واقعی، backup سازمانی و POS وجود ندارند. بهای مواد «مرجع نمونه» است، نه حسابداری خرید و سود خالص. محاسبات از Number فعلی دمو استفاده می‌کنند و معادل Decimal طراحی production نیستند؛ ادعای موتور مالی دقیقِ سازمانی نداریم.

پخش در این دمو انتقال فوری است؛ TRANSIT/تحویل مستقل مقصد هنوز فعال نیست. ثبت فروش بدون recipe/stock کافی رد می‌شود؛ مدل Financial/Consumption مستقل اسناد طراحی هنوز پیاده‌سازی نشده است. این محدودیت‌ها باید در ارائه توضیح داده شوند.

## وضعیت Git و انتشار

این تغییرات فقط branch مستقل‌اند. workflow و manifest هاست، main، دامنه و GitHub Pages تغییر نکرده‌اند. workflow موجود فقط push به main یا اجرای دستی منتشر می‌کند؛ push شاخه feature آن را فعال نمی‌کند. PR به صورت Draft برای بررسی آماده می‌شود. merge، deploy یا اجرای workflow انجام نمی‌شود. commit نهایی و لینک PR پس از ایجاد در پاسخ تحویل گزارش می‌شوند؛ برای جلوگیری از self-reference، SHA خود این commit داخل فایل hard-code نمی‌شود.

## ارزیابی آمادگی جلسه

منطق سناریو و سازگاری داده‌ها از آزمون‌های خودکار عبور کرده‌اند؛ مرز نمایشی/عملیاتی در UI روشن است. **آمادگی نهایی جلسه: مشروط و هنوز تأییدنشده**، چون پذیرش بصری موبایل/دسکتاپ، کنسول اصلاح‌شده و شواهد تصویری بعد از تغییر کامل نشده‌اند. پیش از merge: آزمون مرورگر واقعی، تصاویر قبل/بعد و اجرای سناریو با کلیک، سپس تأیید مالک برای انتشار لازم است.
